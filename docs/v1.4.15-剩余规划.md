## 三、A · 分享二维码（pre4）

### 目标
把一个歌单或单曲生成二维码，扫码后可在手机上打开对应的 B 站地址；歌单则生成一个可复制的分享文本。

### 已核实的实现基础
- `qrcode` 依赖已装（`package.json`），`LoginDialog.tsx:86` 已有 `QRCode.toDataURL(data.url, {...})` 的用法可直接参照。
- 不需要新依赖、不需要主进程能力，纯渲染层。

### 必须定的产品口径（**执行前需拍板**）
1. **二维码内容是什么**：
   - 方案 1（推荐）：歌单 → 生成一段纯文本清单（每首一行 `标题 - B站链接`），二维码装不下就**明确告知并只放歌单首页链接或前 N 首**；
   - 方案 2：单曲 → 直接放该曲的 B 站视频地址。
   - **关键约束**：二维码容量有限（约 2900 字节 @ 纠错 L），一个 50 首的歌单文本装不下。**绝不能静默截断**，必须告诉用户「已放前 N 首」。
2. 单曲二维码的入口位置（播放页 / 歌单详情页）。
3. 是否需要「复制分享文本」按钮（成本极低，建议要）。

### 交付物
- `src/services/shareCode.ts`（纯函数：`buildShareText` / `buildShareQrPayload` / `fitsInQr`）
- `src/components/ShareQrSheet.tsx`（抽屉，复用 `ai-sheet__*` 外壳）
- `tests/shareCode.test.ts`

### 验收标准
- 纯函数测试覆盖：空歌单、超长歌单（断言必须告知截断而非静默）、单曲、特殊字符转义。
- 二维码生成的 payload 长度有上限断言。
- 不新增依赖。

## 四、B · 本地音乐导入（pre5 + pre6）

### 为什么拆两轮
这是本轮唯一需要**新建数据域**的功能：要扫描本地目录、读元数据、持久化索引、接入播放链路。
一轮做完必然超出一个子代理的合理边界，且验收面过宽。

### pre5：扫描与索引（只读，不碰播放）

**目标**：能选一个本地目录，扫描出音频文件，建立可浏览的本地曲库。

- 主进程新增 `electron/localMusic.ts`：
  - `localMusic:scan`：递归扫描用户选的目录，只收 `.mp3/.flac/.m4a/.wav/.ogg`；
  - `localMusic:readTags`：读 ID3/FLAC 元数据。**优先用已有依赖**，没有就只读文件名（**不要为此引入重型新依赖**，若必须引入需单独说明体积）；
  - **必须有限制**：扫描深度上限、文件数上限、单文件大小上限，避免用户选 `C:\` 时卡死。
- platform 层新增 `localMusic` capability。
- 渲染层 `src/services/localMusic.ts`（纯函数：文件名解析、去重、排序）。
- 存储：新增 `localTracks` 键，**不进 `AppSettings`**（它体积大且不是设置）。

**必须提前想清楚的三件事**（写进任务书）：
1. **扫描是长操作**：必须可取消、必须有进度、不能阻塞 UI。
2. **路径是平台相关的**：Windows 反斜杠，鸿蒙/Android 完全不同，能力缺失时整块入口隐藏。
3. **文件会消失**：用户删了文件后索引里还留着，播放时才失败。要有「清理失效条目」的口径。

### pre6：接入播放

- 把本地曲目接进播放链路。**这是本项最大的技术风险点**：
  当前 `resolveAudioPlayableUrl` 只处理 B 站 CDN 地址与 Blob，
  本地文件需要 `file://` 协议或主进程流式读取。
- **必须验证**：`audioGraph` 的 `createMediaElementSource` 对 `file://` 是否同源可用
  （均衡器与可视化依赖它）。若不可用，需要在开启这些功能时先转 Blob。
- 与 `Track` 类型的关系：本地曲目是否复用 `Track`（`bvid` 为空）还是新建类型，
  **执行前需拍板**。

### 验收标准（两轮共同）
- 扫描有进度、可取消、有上限保护。
- 目录不存在/无权限/空目录都有可读提示。
- 播放本地文件时均衡器与可视化要么正常工作，要么**明确降级并告知**，不能静默失效。

## 五、C · `electron/` 类型检查补齐（工程债）

### 问题（已核实）
`tsconfig.include` 只有 `["src","src/types"]`，**主进程代码从未被类型检查**。
esbuild 转译不做类型检查，eslint 不查 `no-undef`，于是形成三重掩盖。
历史上已因此把 OTA 检查与下载全弄断而 tsc/vitest/eslint 三项全绿（v1.4.14-pre9）。

### 方案（需拍板选一）
- **方案 1（推荐）**：新增 `tsconfig.electron.json`，`include: ["electron"]`，
  `npm run typecheck` 同时跑两份。风险最低，不动现有配置。
- 方案 2：把 `electron` 并进主 `tsconfig.include`。改动小，但可能一次暴露出大量存量错误，
  需要预留修复时间。

### 关键提醒
**先跑一遍看存量错误有多少，再决定方案**。若存量错误上百条，方案 1 更稳（可以先只报错不阻断 CI）。

## 九、跨版通用纪律（写进每份任务书）

1. **契约先行**：跨模块的接口由协调者先冻结并提交，再并行派发子代理。
2. **文件边界**：每份任务书写清「只准动这些」与「绝对别碰」，并行任务边界不重叠。
3. **缺口只报不补**：子代理发现契约缺口立即上报，不自行扩大边界。
4. **反向验证**：关键不变式要故意破坏一次，确认测试会红。
   **突变必须落在会被执行的代码形态上**——注释里的假突变会被注释剥离逻辑吃掉（pre3 实测）。
5. **加 `AppSettings` 字段会打红助手注册表守卫**：要么补 `settings.set-*` 动作，
   要么登记为只读结构体，并同步三处硬编码计数。
6. **改设置页要重算高度表**：`MEASURED_GROUP_HEIGHT` 每加一行 +68px（普通行）。
7. **`src/styles/index.css` 只能追加**，绝不整体重写。
8. **`src/` 内禁止 `window.electronAPI` 直调**，已由 `tests/platformGuard.test.ts` 守卫。
9. **改 `electron/` 要单独验证**：tsc 不覆盖，必须让测试真实 import 并调用。
10. **推送走 `https` remote**（`git push https master`），SSH 22 端口本机不通。

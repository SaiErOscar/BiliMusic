# 一键全量数据备份（v1.4.3-pre6）

## 目标与范围

在「设置 → 关于」新增"备份数据"按钮，点按展开四项操作：

- 导出为文件（写 `.bmback` 加密备份文件）
- 从文件导入（读 `.bmback`，口令解密后合并）
- 同步至 WebDAV（固定单文件覆盖，仅 WebDAV 已配置时出现）
- 从 WebDAV 导入（仅 WebDAV 已配置时出现）

WebDAV 两项的出现条件：`window.electronAPI.getWebdavConfig()` 返回 `configured === true`（即用户在"歌单云同步"已填并保存 WebDAV 信息）。

仅 Electron 桌面端（Windows/Mac）；鸿蒙/Capacitor 端无 dialog/fs，入口用现有 `isHarmonyOS` 同类判断隐藏。版本线接当前 v1.4.3，落地为 v1.4.3-pre6。

## 备份负载（导出内容）

从 localStorage 与主进程 Cookie 收集，组成一份快照：

| 数据 | 来源键 | 导入合并策略 |
|---|---|---|
| B 站账号凭证 | `bili:getCookies`（sessdata/biliJct/dedeUserId）+ `bilimusic_user` | 见"账号处理" |
| 我喜欢 | `bilimusic_favorites` + `bilimusic_favorites_deleted` | `mergeItems`（id + likedAt + 墓碑）复用现有算法 |
| 歌单 | `bilimusic_playlists` + `bilimusic_playlists_deleted` | `mergeItems`（id + updatedAt + 墓碑） |
| 最近播放 | `bilimusic_recent` | 按 id 并集去重、时间倒序、截断 50 |
| 下载记录 | `bilimusic_downloads` | 按 id 并集去重、按 downloadedAt 倒序、截断 200 |
| 歌词偏移 | `bilimusic_lyric_offset` | 复用 `mergeLyricOffsets`（本地优先） |
| 设置 | `bilimusic_settings` | 整份配置快照，导入时覆盖（导入确认框内明示） |

`deviceId`、`volume`、`player_state`、缓存类等不纳入备份。

## 文件格式与加密（.bmback）

自创文本封装格式，避免裸 JSON 结构暴露、容纳嵌套数据：

```
BiliMusic-Backup/v1\n
<base64( 信封JSON )>
```

信封（口令派生密钥后用 AES-GCM 加密前的明文）结构：

- `formatVersion`、`exportedAt`、明文 `header`（仅放 formatVersion + exportedAt + `hasAccount` 布尔，不含任何可识别账号信息）
- 密文体 = AES-GCM 加密的完整负载（含 sessdata、dedeUserId、uname、各数据数组）
- KDF 参数 `salt`、`iterations`、`iv`（明文随文件，口令不落盘）

加密：Web Crypto（`crypto.subtle`），PBKDF2-SHA256 派生密钥 → AES-256-GCM。口令由用户在导出时设置，不存储、不可恢复（忘记即无法解密，导入报"口令错误或文件损坏"）。全程在渲染层内存完成，密钥不落盘。

## 数据流与新增能力

1. **导出（文件）**：渲染层收集负载 → 加密为 `.bmback` 文本 → 经新 IPC `backup:saveFile(content)` 调主进程 `dialog.showSaveDialog` + `fs.writeFile`。导出前先弹隐私确认："此文件含 B 站登录凭证等隐私数据，请确认妥善保管，避免泄露。"
2. **导入（文件）**：经新 IPC `backup:openFile()` 调 `dialog.showOpenDialog` + `fs.readFile` 返回文本 → 渲染层口令解密 → 负载比对合并 → 写回 localStorage 并触发各 `*_CHANGED_EVENT`。
3. **同步/导入 WebDAV**：复用现有 `webdavPut` / `webdavGet`，固定远端文件名 `biliMusic-backup.bmback`（覆盖式），内容为同一份 `.bmback` 文本字符串（与现有 `sync.json` 文本上传方式一致）。
4. **Cookie 回写**：`electron/biliApi.ts` 新增 `bili:setCookies` handler，用 `session.defaultSession.cookies.set` 把 sessdata/biliJct/dedeUserId 写回 defaultSession（复用文件内已有的 set 用法）。

## 账号处理（导入时）

解密得到备份的 `dedeUserId`，与当前 `getCookies().dedeUserId` 比较：

- 相同 / 备份无账号 / 当前未登录：正常合并数据；备份有凭证且当前未登录则询问是否用备份凭证登录。
- **不同**：弹询问框，提供两个选项：
  - 保留当前账号（仅合并歌单/收藏等数据，不动登录态）
  - 切换到备份账号（调用 `bili:setCookies` 写回凭证 + 更新 `bilimusic_user` 缓存 + `AuthContext` 用新 Cookie 重新 `getUserInfo` 刷新显示，**免重新登录**）

## 发版流程（沿用 v1.3/v1.4 固定策略）

实现 → 本地测试 → `npm run build`（确认 EXIT_CODE=0、产物生成）→ 版本号+README+CHANGELOG+ROADMAP → commit → annotated tag `v1.4.3-pre6` → SSH push（master + tag）→ 本地构建安装包（带 ELECTRON_MIRROR / ELECTRON_BUILDER_BINARIES_MIRROR）→ 安装实测 → 对话输出产物路径与大小。安装包保持 gitignore 不进仓库。

## 验证要点

- 导出含凭证 → 换未登录环境导入 → 自动登录成功（免重新登录）。
- 口令错误 / 篡改文件 → 解密失败提示，不破坏本地数据。
- 账号不同时两分支：保留当前 / 切换备份，数据均正确合并、不丢墓碑。
- WebDAV 未配置时不出现两个 WebDAV 选项；配置后同步/导入闭环。
- 鸿蒙端入口隐藏、不报错。

## 风险

- 登录凭证跨设备/环境导入后 B 站风控可能要求二次验证（非本项目可控），方案在"切换账号"成功提示里注明若播放异常需重登。
- 设置整份覆盖会冲掉导入端本地个性化偏好，需在导入确认框明确告知。

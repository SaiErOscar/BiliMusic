# v1.4.5 计划：不显示歌词 + 桌面歌词窗显隐动画 + CI 补 AAB

## 背景与事实校正

当前 v1.4.4 正式版已发布（commit f6d24e8）。ROADMAP 表内计划号（含"1.4.5 鸿蒙追版回归"）已作废，鸿蒙线整线迁 v1.5；实际发布号以变更记录为准。经与用户确认，"原来的预定更新"= **CI 补 AAB（Android bundleRelease）**，即记忆页 2026-10-02 收敛版标注的下一个计划槽位 v1.4.5。

本版本共三项，按 v1.3/v1.4 固定流程拆成多个预览版 `1.4.5-preN`，每个本地 Windows 实测通过再推进，全部完成转正式 `1.4.5`。

发版铁律（沿用核心记忆）：每次先 `x.x.x-preN` 预览，commit + annotated tag + SSH push（master + tag），对话输出构建产物路径与大小；打包用工作区外临时 output 目录 `C:/Users/SaiEr/AppData/Local/Temp/bmbuild` 绕开宿主实时扫描锁，产物复制回 `release/` 后还原 `build.directories.output=release`，安装包不进仓库。改文件一律用 file 工具 edit，禁止 sed -i/awk 重写。

## 功能1：不显示歌词（pre1）

### 需求拆解
点击"切换歌词"时，候选抽屉**置顶**插入一条"不显示歌词"项，样式与普通候选一致但无 QQ/网易/LRCLIB 来源 tag。选中后：
1. 该曲目被永久标记为"无歌词"（不同于"自动匹配没找到"的临时 empty 态，不随 24h TTL 过期重搜）；
2. 播放页歌词区显示"无歌词"；
3. 桌面歌词窗显示"无歌词"；
4. 下载时无论 `同时下载歌词(.lrc)` / `写入歌手属性` 如何设置，都不产出歌词、不写入候选歌手。

### 数据模型（`src/services/lyrics.ts`）
- 缓存结构 `CacheEntry` 由 `{status:'ok'|'miss'}` 扩展第三态 `{status:'none'}`（无 ts、不过期）。
- `LyricResult` 新增可选字段 `noLyric?: boolean`。
- 新增导出常量 `NO_LYRIC_CANDIDATE: LyricCandidate`（`id:'none'`、`source` 复用现类型或新增 `'none'` 联合，`trackName:'不显示歌词'`、无来源）。抽屉置顶项直接用它。
- `getLyricForTrack`：命中 `status:'none'` 时返回 `{ noLyric:true, lines:[], synced:false, instrumental:false, offset:0, trackName:'', artistName:'', sourceId:'none' }`，**不走** searchBestCandidate（保证用户选择优先于自动匹配、永久生效）。
- `chooseLyricCandidate` 或新增 `setNoLyric(trackId)`：当选中的候选 `id==='none'`，写 `cache[trackId]={status:'none'}` 并返回 noLyric result（不发起取词网络请求）。
- `LYRIC_SOURCE_LABELS` 不为 none 增加标签（保持无 tag 视觉）。

### Hook（`src/hooks/useLyrics.ts`）
- `LyricStatus` 新增 `'none'`。
- `load` 与 `choose`：拿到 `res.noLyric===true` → `setStatus('none')`、`setResult(res)`（不再进 empty 分支；注意当前 empty 判定是 `!res.lines.length && !res.instrumental`，需在判定前优先短路 noLyric）。

### 播放页（`src/components/NowPlaying.tsx`）
- 抽屉 `lyrics-drawer__list` 顶部渲染固定的"不显示歌词"候选项（复用 `.lyrics-candidate` 样式，**省略 `<em class="lyrics-drawer__source">` 来源标签**），点击 → `pick(NO_LYRIC_CANDIDATE)`（pick 内对 `id==='none'` 走 setNoLyric 分支，不触发取词）。
- `status==='none'` 时歌词区显示"无歌词"占位（新分支，文案与 empty 的"暂无歌词"区分；保留底部控制栏，使 `status` 显示判定从 `ok||unsynced` 扩为 `ok||unsynced||none`，让"切换歌词"按钮在 none 态仍可用以便改回）。

### 下载链路（`src/components/DownloadButton.tsx`、`src/services/batchDownloadStore.ts`）
- 两处均有 `if (lyricResult) { if(embedMeta && lyricResult.artistName) ...; if(includeLyric && lyricResult.lines.length>0) lyricContent=formatLrc(...) }`。
- 显式加保护 `if (lyricResult && !lyricResult.noLyric)`：none 态 `lines.length===0` 且 `artistName===''` 已天然跳过 lyricContent 与 artist，但显式判更稳，杜绝日后 LyricResult 结构变化导致 none 态误触发。确认"无论如何不下载歌词"由 `status:'none'` 永久缓存保证（下载链路同样调 getLyricForTrack，命中 none 即返回空）。

### 桌面歌词窗（`electron/miniWindows.ts` renderLyric + 状态来源）
- `renderLyric`：当前 `!state.synced || lyricLines.length===0` 显示 `state.title||state.artist||'暂无歌词'`。需让"无歌词"标记透传到 miniState：`useMiniWindowSync` 推送时，若 `status==='none'` 则下发一个 `noLyric:true` 标志（MiniPlayerState 增可选字段），歌词窗据此在 `hasTrack && noLyric` 时显示"无歌词"（idle 样式）。
- `MiniPlayerState` 类型（`src/types/electron.d.ts` 与主进程）补 `noLyric?: boolean`；`mini:state` 合并行按既有"undefined 保留旧值"风格纳入。

### 测试与验证（pre1）
- `tests/lyrics.test.ts`（或现有歌词测试）补：none 缓存命中 getLyricForTrack 返回 noLyric、不过期、下载判定 lines 空；useLyrics none 态。
- vitest 全绿、tsc/eslint 0 error。
- 本地构建 Windows 安装包，实测：选"不显示歌词"→播放页/桌面歌词显示"无歌词"、切歌往返保持、下载无 .lrc 无歌手、可从抽屉改回正常歌词。通过后 commit+tag `v1.4.5-pre1`+push，输出产物路径与大小。

## 功能2：桌面歌词窗显隐动画（pre2）

### 需求
任何实际切换歌词窗显示状态时出现淡入/淡出动画（含点击"显示/隐藏桌面歌词"、托盘切换、歌词窗右上 ✕、进入/退出播放页触发的抑制-恢复等所有走状态机的路径）。

### 设计（CSS 淡入淡出，不用主进程 setOpacity）
transparent 无边框 Windows 窗用 `win.setOpacity()` 逐帧在透明窗上可靠性存疑，改为内容容器 CSS transition + 主进程"延迟真正 hide"，所有可见性切换统一经状态机 `applyLyricVisibility()`，改这一处即覆盖全部路径。

### 实现
- **歌词窗内联 HTML（`getLyricHtml`）**：给 `.wrap`（或新建最外层容器）加 `opacity` + `transform: translateY()` 过渡；默认态与 `.hidden` 类做淡出/上移。脚本用 preload 新增的可见性通道切换 class。
- **preload（`electron/mini-preload.cjs`）**：在 `miniAPI` 增加 `onVisibility(cb)`（监听 `mini:visibility` IPC），保留 `onState`/`sendCommand`。
- **主进程（`electron/miniWindows.ts`）**：
  - `showLyricWindow()`：`createLyricWindow()` → 先 `win.showInactive()`，随即 `win.webContents.send('mini:visibility',{show:true})` 触发渲染层淡入（配合 broadcast）。首帧避免旧内容闪现：新建窗时初始 `.wrap` 置隐藏态，显示时再淡入。
  - `hideLyricWindow()`：不再瞬时 `hide()`。改为 `lyricWindow.webContents.send('mini:visibility',{show:false})` 通知淡出 + `setTimeout(()=>{ if(仍应隐藏) lyricWindow?.hide() }, DURATION+缓冲)`。用一个 `hideToken`/最新意图标志防止淡出期间又被 show（show 时清 pending hide timer 并立即显示）。`destroyLyricWindow`（退出）保持瞬时 destroy 不等动画。
  - 隐藏后 `notifyLyricVisible()` 调用时机：状态机语义上"意图已切换"即时上报（托盘文案立即更新），实际窗口消失延后由动画计时器负责；确保 `isLyricVisible()` 判定与实际显示一致，避免淡出中托盘/主窗口读到错误可见性（可让 notify 读意图态或维持现状，pre2 实测校准）。
- **动画时长**：淡入 ~220ms、淡出 ~180ms（ease），可先常量，实测调。尊重"快速连续切换"不抖动：pending-hide 计时器单一归属。

### 验证（pre2）
- 覆盖路径实测：主窗口"显示/隐藏桌面歌词"、托盘切换、歌词窗 ✕、进入播放页（抑制→隐藏）/退出播放页（恢复→显示）、歌词窗"打开播放器"后再返回。每条均有淡入/淡出。
- vitest/tsc/eslint 通过；本地构建 + 实测 commit+tag `v1.4.5-pre2`+push，输出产物。

## 功能3：CI 补 AAB（pre3 + 转正）

### 现状
`.github/workflows/build.yml` 的 android job 已产 debug APK + release APK（`assembleDebug`/`assembleRelease`），无 AAB；release job 下载 `android-release-apk` 上传 Release。签名走 `HAS_RELEASE_KEYSTORE` 门控。

### 实现
- android job 在 `Build release APK` 后新增 `Build release AAB`：`if: env.HAS_RELEASE_KEYSTORE == 'true'`、`working-directory: android`、`bash gradlew bundleRelease --no-daemon`，产物路径 `android/app/build/outputs/bundle/release/*.aab`。
- 新增 `Upload release AAB`（`actions/upload-artifact@v4`，name `android-release-aab`，path 同上，`if-no-files-found: error`，retention-days 14，同样 HAS_RELEASE_KEYSTORE 门控）。
- release job：仿 "Download Android release APK" 增加 "Download Android release AAB"（name `android-release-aab`、path `release-assets`），使 `softprops/action-gh-release` 的 `files: release-assets/**` 自动把 `.aab` 一并发布。
- debug 不产 AAB（Play 内部测试也需签名的 AAB，debug 无签名意义小，保持只 APK）。

## 风险与开放点

- **功能1 none 态与 embedMeta 歌手**：用户主动选"无歌词"后 artistName 为空，"写入歌手属性"也拿不到歌手。符合"不下载歌词"语义，视为预期；转正说明里点明。
- **功能2 淡出期间可见性上报**：`isLyricVisible()` 在淡出计时窗口内与实际显示可能短暂不一致，pre2 实测校准 notify 时机，避免托盘/按钮态抖动。
- **功能3 AAB 体积/命名**：Play 上架后续（v1.4.7+ Android WebDAV）才实际消费 AAB，本版仅产出不接入上架流程。
